## Learn

A **pseudorandom number generator** is built from an arbitrarily long chain of **D-type flip-flops** arranged as a shift register, mixed with **XOR gates** whose inputs are distributed among the Q outputs and whose outputs feed the stages of the register. It is "pseudo" random because **the sequence of numbers will eventually begin to repeat itself**.

**N-input XOR:** the output is TRUE when the number of TRUE inputs is **odd**. It can be built as a cascade of two-input XORs: f(a,b,c) = C XOR (A XOR B). The result is a circuit that outputs 1 when the number of 1s at its inputs is odd and 0 when it is even, useful as a **parity generator** or modulo-2 adder.

**Simulation step (40% of the lab grade, in Logisim):** twelve D-type flip-flops, eight XOR gates (two-input to match the hardware), one XOR output fed back to the first flip-flop, XOR inputs connected to Q or ~Q outputs of the eight flip-flops, XOR outputs connected randomly to the inputs of the other seven. Run it, log the state sequence (Logisim's logging exports to Excel), and count the states before it repeats; over 100 non-repeating states is easy to achieve.

## Worked example

*Three-input XOR with inputs 1, 1, 1. Output?*

1. A xor B = 1 xor 1 = 0.
2. Then 1 xor C(=1) = 0 xor... compute: (1 xor 1) xor 1 = 0 xor 1 = **1**.
3. Three ones is an odd count, so the output is 1, consistent with the parity rule.

## Try it

*Why does a pseudorandom sequence from an 8-bit output repeat after at most 256 values?*

???

The observed state has only 2^8 = 256 values; once a value recurs, a deterministic circuit follows the same path again. (If hidden state exists the repeat can take longer, but the same logic applies to the full state.)
