## Learn

Interrupts are asynchronous, so they can arrive while another **ISR** is running. To decide who wins they are given **priorities**: a more important interrupt **preempts** a less important one, and a lower-priority interrupt **waits**. What counts as important depends on the system: a fast data stream you must not drop, a battery monitor that must save the machine's state, or protection of human life.

- **NMI** is the interrupt that **cannot be masked**. It is reserved for catastrophic events, such as power loss or a memory failure, and execution can return to the interrupted code after it is served. On the 68K the lowest interrupt priority is **1** and the NMI is **7**.
- **RESET** is "a very dramatic interrupt": it clears registers, sets a known state and starts again from a known location. It does not return. The RESET line has to be held for 50 to several hundred clock cycles so the processor's state machine reaches the right state.
- **Exceptions** are generated by the **program**: a memory access error, an illegal instruction, divide by zero. They are handled like interrupts but **cannot be masked**.
- A real-time operating system always lets a ready **higher-priority task preempt** a lower one. Its hazard is **priority inversion**, where a low-priority task keeps a resource that a blocked high-priority task needs.

## Worked example

*Interrupt A has priority 3 and B has priority 5. A's ISR is running when B arrives, and later C (priority 2) arrives while B's ISR runs. In what order do the routines finish?*

1. B (5) outranks A (3), so B **preempts** A.
2. C (2) is lower than B, so C **waits**.
3. B finishes. Then A (3) resumes ahead of C (2), because the processor takes the highest pending priority.
4. A finishes, then C runs.

Order of completion: **B, A, C**.

*A divide instruction divides by zero while an interrupt of priority 4 is being served. Is the resulting event an interrupt that has to wait, or something else?*
